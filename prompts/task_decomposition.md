### 拆解原则：
1. 原子性：
    - 每个子问题应尽可能简单，不可再拆分，确保每个子问题都可被独立求解
    - 进行拆分时，应判断问题是否已是原子问题
    - 查询、统计、计算等步骤均需要拆分求解，不要合并到一个子问题中
2. 基于可调用的函数工具：
    - 任务拆解必须基于提供的函数工具，避免拆解多余的子任务
    - 在求参数的平均值、最大值、最小值、众数、总和、数据条数等数据时，**无需查询所有数据**，调用aggregate_data函数**一步**即可完成
3. 结构化：
    - 如果问题包含假设条件或格式要求，应单独列出
    - 问题中设备的关键动作不要拆开
    - 根据可调用的函数工具进行仔细思考判断，无需返回思考过程，只需输出 JSON 结果
4. 必要性：
    - 拆解时应确保每个子问题都是解决原问题的必要步骤
    - 注意题目的最终目标，不要拆解出无关紧要的子问题
    - 拆解后的子问题应尽可能少，但不能遗漏任何必要步骤
5. 其他要求：
    - 题目未明确给出年份时，默认 2024 年
    - 若问题涉及某一天内的某个动作时间点，需计算该动作当天发生的所有时间点，而非仅第一次发生时间

### 输出格式
返回JSON对象，包含以下字段：
  - assumption：假设条件。
  - format_requirement：格式要求（如时间输出格式要求为XX:XX）。
  - contains_time：是否包含时间（true/false）。
  - subtasks：子问题列表，每个子问题均为原子问题，包含以下字段：
    - task_id：唯一标识，原始问题的 ID 固定为 0，子问题 ID 从 1 开始递增。
    - level：子任务层级，从 1 开始计数。
    - question：子问题描述，不包含假设条件和格式要求。
    - parent_ids：依赖的父问题 ID 列表（无依赖则为[0]）。
  - chain_of_subtasks：子问题的执行顺序和依赖关系。
